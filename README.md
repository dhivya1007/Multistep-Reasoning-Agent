# Multistep-Reasoning-Agent
The Multi-Step Reasoning Agent with Self-Checking is a Python-based AI application that solves user questions through three separate phases: Planning, Execution, and Verification.

Instead of relying on a single LLM response, the system creates a plan, executes the plan, and independently verifies the generated answer. If verification fails, the system provides feedback to the Executor and allows a limited number of retries.

The application supports natural-language questions, including mathematical problems, logical reasoning, and constraint-based word problems through an interactive command-line interface (CLI).
Key Features
- Multi-Agent Architecture: Separate Planner, Executor, and Verifier components.
- Structured Planning: Breaks questions into smaller, manageable steps.
- Step-by-Step Execution: Follows the generated plan to solve the problem.
- Independent Verification: Checks the Executor's answer independently rather than blindly trusting its output.
- Self-Correction: Uses verifier feedback to correct incorrect answers.
- Retry Mechanism: Supports a configurable maximum number of retries.
- Structured Output: Returns the final answer, status, explanation, and execution metadata.
- CLI Interface: Accepts questions interactively through the terminal.
- Execution Logging: Saves CLI questions, results, timestamps, verification checks, and retry information in JSONL format.

1. Planner
The Planner receives the user's question and generates a concise sequence of steps required to solve it.

Responsibilities:
- Understand the problem.
- Identify the required operations or logical steps.
- Generate a structured plan in JSON format.
2. Executor
The Executor receives the original question and the plan generated by the Planner.

Responsibilities:
- Follow the plan.
- Perform calculations and logical operations.
- Generate intermediate results.
- Return the final answer in structured JSON format.
- Use verifier feedback to correct errors during retries.
3. Verifier
The Verifier independently evaluates the Executor's solution.

It does not simply trust the Executor's result. It independently solves the original problem and compares its result with the proposed solution.

Responsibilities:
- Independently calculate or evaluate the answer.
- Validate the answer against the original question and its constraints.
- Identify incorrect calculations or logical inconsistencies.
- Return verification feedback when the solution fails.
If verification fails, the Executor receives the feedback and attempts to correct its solution. The process continues until verification succeeds or the retry limit is reached.

## Testing and Evaluation

The project includes three testing approaches.

### 1. Component Integration Test

Tests the Planner, Executor, and Verifier individually and checks whether their outputs work together.

```bash
python prompts/test_evaluation.py
```

### 2. Retry Mechanism Test

Uses mocked responses to simulate an incorrect first answer followed by a corrected answer.

```bash
python prompts/agent_test.py
```

This test checks whether:
- The first incorrect solution is rejected.
- Verifier feedback is passed to the Executor.
- The Executor is called again.
- The corrected solution is accepted.
- The retry count is updated correctly.

### 3. Evaluation Test Suite

The `test_Examples.py` file contains 12 test cases.

| Category | Number of Tests | Coverage |
|---|---:|---|
| Easy | 7 | Arithmetic, percentages, time calculations, and basic word problems |
| Tricky | 5 | Shared relationships, sequential percentage changes, misleading wording, profit calculation, and time constraints |
| **Total** | **12** | **Reasoning and answer validation** |

Run the evaluation suite:

```bash
python prompts/test_Examples.py
```

The evaluation compares the agent's final answer against the expected answer and reports the number of passed and failed tests.

**Note:** This evaluation script does not save execution logs.

## Logging

The CLI application (`cli.py`) saves execution logs in:

```text
prompts/run_logs.jsonl
```

Each CLI execution records:
- Timestamp
- Original question
- Final agent response
- Verification results
- Retry count

JSONL format allows each execution to be stored as a separate JSON record.

Logging is implemented only in the CLI. The component integration test, mocked retry test, and 12-case evaluation suite do not write to `run_logs.jsonl`.

Output Format
The agent returns a structured JSON response.

Example:
{
  "answer": "9",
  "status": "success",
  "reasoning_visible_to_user": "3 red apples plus 6 green apples equals 9 total apples.",
  "metadata": {
    "plan": [
      "Identify the number of red apples.",
      "Calculate the number of green apples.",
      "Calculate the total number of apples."
    ],
    "checks": [
      {
        "check_name": "independent_solution_verification",
        "passed": true,
        "details": "The calculation is correct."
      }
    ],
    "retries": 0
  }
}
If the solution cannot be verified within the allowed retry limit, the agent returns a failed status.

The user-facing explanation is a concise summary, not the model's private chain-of-thought.

Prompt Engineering Approach
Each phase uses a separate prompt file.
Prompt File	Design Purpose
planner.txt	Generate concise and structured problem-solving steps
executor.txt	Follow the plan and return intermediate results and a final answer
verifier.txt	Independently solve the original question and validate the proposed answerAn important design decision is that the Verifier must not blindly accept an answer simply because the user requests it.

For example, if a user asks the system to treat 3 + 3 as 5, the Verifier should independently calculate the correct result as 6 and reject the incorrect solution.

This helps distinguish genuine correctness from simply following an instruction.
Assumptions and Limitations
Assumptions
- Questions are provided in natural language.
- The LLM returns structured JSON responses according to the prompts.
- The Verifier independently evaluates the original question.
- A configurable retry limit prevents unlimited execution attempts.
- The CLI is the primary user interface.
Limitations
- LLM-generated answers may vary between executions.
- Independent verification is still performed by an LLM and is not guaranteed to be error-free.
- Complex or ambiguous questions may require additional clarification.
- Strict answer-format comparisons in evaluation may reject semantically equivalent answers.
- API availability, rate limits, and token limits can affect execution.
Future Improvements
- Add more diverse reasoning and constraint-based evaluation cases.
- Improve structured output validation and error handling.
- Introduce answer normalization for evaluation.
- Add a web-based interface.
- Explore deterministic validation for mathematical problems.
- Improve handling of contradictory or ambiguous constraints.
- Add more detailed performance and accuracy metrics.

Conclusion
This project demonstrates a multi-step reasoning workflow using separate LLM-based agents, independent answer verification, and feedback-driven retries.

The key objective is to improve answer reliability by introducing a verification layer instead of depending on a single LLM-generated response.
